### F-C — CSP hardening — DONE ✅ (CSP only). Asset-scope narrowing DEFERRED (token was wrong).
`src-tauri/tauri.conf.json`: replaced `csp: null` with the strict policy from
`docs/security-hardening.md` + `blob:` widening (three.js loads embedded GLB
textures via object URLs; Meshy Refine returns textured GLBs). **Left
`assetProtocol.scope` at `["**"]`.**

**Why the scope was NOT narrowed:** the proposal's `$LOCALAPPDATA/Conjure3D/**`
uses a **non-existent Tauri scope token**. Verified against Tauri 2.11 source
(`path/mod.rs:216` `from_variable`; `scope/fs.rs:184` `Scope::new`→`path().parse()`):
valid tokens are `$LOCALDATA / $APPLOCALDATA / $APPDATA / $RESOURCE / $APPCONFIG`.
An unknown token is pushed as a literal, so `$LOCALAPPDATA/…` would match no real
path and **silently break every 3D preview** — worse than `["**"]`, and invisible
to a boot/parse check (the app would still start). The correct value is
`$LOCALDATA/Conjure3D/**`; enabling it needs a live generate→preview test
(couldn't drive without spending Meshy credits). With the strict CSP already
blocking the XSS vector, the scope narrowing is low-value belt-and-braces — the
audit rated `["**"]` acceptable even with no CSP. Full write-up in
`security-hardening.md`.

the frontend has **no Open/Save-project UI** — `grep` finds zero `project.load` /
